# Galaxy S22 실기기 사진 검색 캐시 측정

Galaxy S22 `SM-S901N`, Android 16 / API 36, arm64 Expo development APK `1.0.0`. 앱 기준 Git `c1d241267d99f6fbda526d9e38de771b6b8d7916`와 로컬 계측 변경, APK SHA-256 `6F54F5866B27B187391E77DFFE70EEBDFB7B3852BC0CE38D99F99216AE0235FA`. JS 번들은 USB Metro에서 공급했고, 여행 기간과 설정은 앱의 개발용 mock 데이터다. 갤러리 열람·인코딩·캐시·토크나이저·ONNX·순위·UI는 연결된 폰에서 실행했다. 파일 크기로 계산한 모델 버전 `el9kw5`, 전체 사진 권한. 사진은 60장 합성 원본에서 만든 JPEG이며, 후보 기간을 맞추려고 기기의 당시 시각 및 KST 오프셋을 EXIF에 넣었다. 계측과 mock이 켜진 코드에서만 지정된 합성 파일을 골랐다.

폰 시계는 PC 날짜와 달랐다. 화면·인덱싱·검색 시간차는 모두 같은 폰 로그의 시각으로 계산했다. 메모리 구간 매핑은 PC에서 로그를 수신한 시각을 이용했다. 최초 모델 다운로드 5,601ms는 A/B/C에서 제외했다. 다운로드 전의 탐색 실패와 테스트 외 사진이 포함된 사전 확인은 실측 표에 넣지 않았다.

## 100장 실험

| 조건 | 실제 후보 | 신규 / 재사용 | 정리 시작 → 준비 | 화면 진입 → 준비 | 표본 최대 PSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| A · 캐시 없음 | 100 | 100 / 0 | **26.339초** | 32.801초 | 1,004,985 KiB, 22표본 |
| B · 강제 종료 후 재진입 | 100 | 0 / 100 | **1.593초** | 2.528초 | 878,265 KiB, 2표본 |
| C · 10장 추가 | 110 | 10 / 100 | **4.017초** | 4.991초 | 904,423 KiB, 3표본 |

조건별 1회다. A와 B에서 첫 수동 탭까지 걸린 시간이 다르므로 캐시 비교는 정리 버튼 로그에서 준비 프레임까지를 기준으로 삼았다. A의 이미지 전처리는 20.016초, 이미지 추론은 4.641초였다. B의 캐시 읽기는 17ms였고 이미지 추론은 없었다. 갤러리 모형과 시작 시점은 [실행 기준](../README.md)에 기록했다. 타일은 비슷한 사진을 접기 때문에 A와 B 모두 100장 검색 가능과 표시 타일 49장이 함께 기록됐다. 준비 전 일부 사진이 표시되는 시각은 이번 100장 정량 구간에서 별도로 채취하지 않았다. ## 990장 → 1,000장 실험

| 조건 | 실제 후보 | 신규 / 재사용 | 정리 시작 → 준비 | 화면 진입 → 준비 | 사진 묶기 | 표본 최대 PSS |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A · 캐시 없음 | 990 | 990 / 0 | **319.019초** | 319.993초 | 18.836초 | 1,042,114 KiB, 257표본 |
| B · 강제 종료 후 재진입 | 990 | 0 / 990 | **20.651초** | 21.516초 | 18.485초 | 862,250 KiB, 17표본 |
| C · 10장 추가 | 1,000 | 10 / 990 | **17.627초** | 18.638초 | 13.273초 | 947,654 KiB, 15표본 |
| 묶기 개선 후 재진입 | 1,000 | 0 / 1,000 | **2.036초** | 3.015초 | **0.228초** | 886,874 KiB, 2표본 |

각 행 1회다. A의 이미지 전처리 240.916초, 이미지 추론 55.507초가 첫 인덱싱을 지배했다. B는 이미지 인코딩을 전부 건너뛰었고 캐시 읽기는 131ms였으나, 유사 사진 묶기가 18.485초를 차지했다. B의 ‘비빔밥’은 A와 **19개 결과의 순서·점수 모두 일치**했다. C에서는 추가한 사진 10장만 새로 인코딩됐고 ‘카드키’에서 새 `EODIBENCH_NEW_01000.jpg`가 1위였다. 앱의 여행 앨범 코드 제한까지 도달했고, 앱이 5,000장을 색인하는 설정은 지원하지 않는다. 5,000장을 투입하는 별도 한계 시험은 실행하지 않았다. ### 개선한 구간

`groupSimilar`에서 완전히 동일한 packed 임베딩끼리는 동일한 벡터 쌍의 내적 판정을 재사용한다. 기존 순서의 union 연산과 유사도 임계값을 유지했다. 같은 기기·모델·사진 1,000장으로 **묶기 단계만 13.273초 → 0.228초**를 관측했다. 전체 준비 시간은 기준 C에 신규 10장 인코딩이 포함되고 개선 후 행은 전부 캐시 적중이라, 두 행의 전체 차이를 최적화 폭으로 사용하지 않는다. 타일 수 50개, ‘카드키’의 **60개 결과 순서와 점수 모두 일치**했다. 검색·모델 규칙 테스트 21건을 통과했다. 이 합성 앨범은 같은 원본에서 만든 사진을 여러 장 사용하므로 완전히 동일한 임베딩이 드문 실제 앨범에는 이 개선 폭을 일반화할 수 없다. ## 실측 제목 후보

1. **여행 사진 990장의 임베딩을 재사용해 Galaxy S22 검색 준비 시간을 319.02초에서 20.65초로 단축**
2. **여행 사진 10장을 추가할 때 기존 990장을 재사용하고, 추가한 카드키 사진을 한국어 검색 1위로 찾음**
3. **동일 임베딩 쌍의 유사도 판정을 재사용해 반복 합성 사진 1,000장의 묶기 단계를 13.27초에서 0.23초로 단축**

기존 임베딩 캐시의 효과와 별도의 묶기 최적화를 측정했다. 모델 리포트의 4.3GB → 191 MiB 및 Top-5 78.5%, Windows CPU 재현 Top-1 27.3% → 47.4%와 실기기 지연은 별개의 결과다.
