## 검색과 API 호출 시점

1. **화면 진입** · `PhotoSearchScreen`이 `GET /me/trips`(페이지 순회)와 `GET /me/settings`를 조회한다. 날짜가 있는 여행만 갤러리 기간에 반영한다. 모델이 없어 처음 받는 경우 모델 다운로드 URL도 필요하다. 온라인 사전 준비 없이 실행한 앱의 최초 진입이 오프라인에서 된다고 볼 수 없다. [검색 화면](../frontend/src/features/ondevice/screens/photo-search-screen.tsx) · [모델 다운로드](../frontend/src/features/ondevice/model-store.ts)
2. **정리와 질의** · 모델·여행 기간·사진 권한이 준비되면 로컬 갤러리를 읽고 사진 임베딩을 작성 또는 재사용한다. 입력이 300ms 멈추면 로컬 ONNX에서 문장 벡터를 만들고, 내적과 상대 점수 필터를 계산해 타일을 만든다. 이 흐름에서 검색어·사진 임베딩을 서버로 보내는 호출은 없다. 이미 준비한 화면에서 검색 추론은 코드상 오프라인으로 가능하다. [갤러리 훅](../frontend/src/features/ondevice/use-gallery-ai.ts) · [ONNX 엔진](../frontend/src/features/ondevice/engine.ts)
3. **선택 사진 업로드 후** · 등록된 사진 중 기기 분류 결과가 있는 항목은 `POST /trips/{tripId}/photo-classifications/device`로 사진 ID·버전·주제·그룹 키를 저장한다. 이 호출은 검색 제출과 별개다. 기기 결과가 없는 등록 사진은 설정이 `AUTO`일 때 서버 분류 경로를 쓴다. [업로드 훅](../frontend/src/features/photo/hooks/use-photo-upload.ts) · [사진 API](../frontend/src/features/photo/api.ts)

## 새 Android 실기기 실행

**미실행.** 작업 시작과 재확인 시 Android SDK `adb devices -l`에 연결된 기기가 없었다. 새 검증 빌드·설치 SHA, 기기 모델·OS, 기기 앨범 장수, 실제 로드한 모델 버전, 검색 화면 캡처, 앱 재시작 후 첫 검색·반복 검색 시간은 모두 미측정이다. `el9kw5`는 로컬 파일과 소스에서 도출한 버전이라 기기 기록으로 사용하지 않았다. 종전 Galaxy S10 5G(Android 12)의 409장 정리 및 질의 16회 0.14–0.38초는 **별도 사진실험 앱의 과거 로그**다. 새 앱 화면 표시까지의 측정값으로 인용할 수 없다.

## 새 재실행 · 기존 평가 사진 1,931장

기존 평가와 같은 `eval256.npz`의 256×256 이미지, `eval_files.json` 순서와 저장된 한국어 `query`를 사용했다. 이미지·질의의 1:1 대응을 정답으로 삼았다. 두 모델에 같은 정규화 픽셀과 같은 질문을 넣고 각각의 토크나이저로 처리했다. 양쪽 모두 전체 앨범에서 코사인 순위를 계산했다. 이 세트는 전부 대응 정답이 있고, 검색어와 정답 사진의 대응은 기존 기록을 사용했다. 실제 검색에선 적합할 수 있는 다른 사진을 추가 정답으로 세지 않았고, 이 세트에서는 무정답 거절 성능을 측정할 수 없다. 공개용 결과는 사진·질의 원문 대신 순서 기반 익명 ID만 남긴다.

| 지표 | 원본 webli B-32 | 폰용 ONNX |
| --- | ---: | ---: |
| Top-1 | 527/1,931 (27.3%) | **915/1,931 (47.4%)** |
| Top-5 | 1,007/1,931 (52.1%) | **1,500/1,931 (77.7%)** |

Top-1 적중으로 바뀐 질의는 **473개**, 적중을 잃은 질의는 **85개**다. `q0004`의 정답 `h0004`는 4위 → 1위였고 상대 모델의 1위는 `h0008`이었다. `q0014`의 정답 `h0014`는 1위 → 2위였고 폰용 모델은 `h1604`를 1위에 올렸다. 해당 수치는 이번에 실제 추론으로 다시 계산했다. 이전 리포트의 `77.7–78.5%` 범위와 기존 합성 60장 결과는 그대로 보존했다. [1,931개 질의별 익명 비교 CSV](search-historical-comparison.csv)

## 공개용 사례

- **정상 `q0001`** · 같은 일몰 질문과 같은 60장으로 원본 B-32의 1위는 `p08`, 폰용 모델의 1위는 정답 `l11-b`였다. 두 모델의 순위와 정답 ID를 CSV에 남겼다.
- **실패 `q0006`** · 고래 사진이 없는데 앱의 상대 필터는 `f09` 해산물 시장 사진을 반환했다. 폰용 최고 점수는 0.04826으로 별도 절대 하한을 적용한 이번 실험에서는 결과가 보류된다. 제품의 상대 필터 동작을 바꾸지 않았다. [이전 실패 증거 카드](failure-result.png)

공개용 CSV와 보고서에는 원본 사진·내부 학습 데이터·파일 경로·개인정보를 넣지 않았다.

비교 스크립트는 `python compare_search.py <폰 모델 폴더> <합성 사진 폴더> <출력.csv>`로 실행한다. 기존 평가에는 두 번째 인수로 모델·평가 보관 루트를 주고 끝에 `historical`을 붙인다. Python의 PyTorch·open_clip·ONNX Runtime·NumPy·Pillow, 원본 SigLIP2 모델 캐시, Node 24 및 공개 커밋을 읽을 수 있는 Git 작업 폴더가 필요하다. 두 경로 모두 Windows CPU 4스레드로 실행했다.
