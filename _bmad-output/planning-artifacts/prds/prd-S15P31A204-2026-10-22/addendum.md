# 어디로그 설계 입력

기준: [PRD](./prd.md), [회의 기록](./meeting-notes.md). 아래는 사용자가 준 구현 의도·사용 경험 참고이며 기술 공급자나 방식의 확정이 아니다.

- **날씨 대안·준비물:** 회의에서 LLM 활용 의도를 명시했다. 사실 데이터인 날씨·장소·영업 정보와 모델의 대안 설명을 구분하고, 모델·공급자·조회·갱신 방식은 후속 설계에서 정한다.
- **그룹 즐겨찾기:** 인스타그램 릴스의 그룹 저장처럼 여러 사람이 함께 모으는 경험이 참고다. 인스타그램 계정 연결·릴스 자동 수집을 요구한 것은 아니다.
- **링크·캡처:** 장소 식별 결과를 지도에 자동으로 보여주는 것이 사용자 목표다. OCR·이미지 인식·URL 해석·장소 검색의 조합과 지원 사이트·파일 형식은 검증 후 정한다.
- **카카오톡 초대 링크:** 카카오톡을 통한 동행 초대 공유는 범위에 포함한다. 카카오 로그인·카카오 친구 목록·비공개 콘텐츠 수집은 별도 결정 없이 추가하지 않는다.
- **자동 일정 재조정:** 장소가 빠진 뒤 일정 재계산이 자동으로 이뤄지는 목표다. 기존 확정 코스를 즉시 덮어쓸지, 변경안을 보여준 뒤 확인받을지는 Q-6에서 결정한다.
- **기본 CRUD:** 기능별 생성·조회·수정·삭제와 권한·파생 결과 영향을 함께 명세한다. 추천·지도 집계 자체를 사용자가 임의 조작하는 데이터로 구현하지 않는다.

## 추천 정상 동작의 대표 검증 사례 제안

아래는 합의 전 검증 입력 예시다. 추천 순위·개수·정확한 가중치는 정하지 않는다. 제품·AI·개발이 Q-5·9를 정할 때 구체적인 후보 자료와 기대 결과를 함께 확정한다.

| 사례 | 대표 입력 | 기대할 결과의 특성 |
| --- | --- | --- |
| 저장 겹침과 서로 다른 취향 | 세은·승기가 같은 카페를 그룹에 저장. 세은은 카페, 승기는 산책 선호 | 같은 장소의 두 저장을 겹침으로 식별. 카페 추천 이유와 승기의 산책 선호를 어떻게 반영했는지 설명. 한 사람의 선호를 모두의 합의로 표시하지 않음 |
| 겹침 없는 동행 | 세은·승기가 서로 다른 장소만 그룹에 저장 | 겹침이 있다고 꾸미지 않음. 각자의 허용 취향·여행 조건에 근거한 추천을 구분해 제시 |
| 개인 보관함·미공유 취향 | 인경의 개인 보관함과 비공개 취향이 있고, 인경도 여행 그룹에는 참여 | 인경의 비공개 장소·취향·원본을 그룹 추천 이유에 노출하지 않음. 반영 여부의 설명도 허용된 범위만 표시 |
| 좋아요와 실제 방문 구분 | 방문하지 않은 장소의 피드에 좋아요를 남기고 나중에 취소 | 좋아요를 방문·평점으로 계산하지 않음. 취소 후 신규 추천 입력 처리는 합의된 Q-5c를 따름 |
| 최근 트렌드의 근거 부족 | 기준 기간의 평가·반응이 합의된 최소 조건에 미달 | 최근 인기라고 단정하지 않음. 자료 부족과 개인화 추천을 구분. 최소 조건·대체 노출은 Q-9 합의 후 고정 |
