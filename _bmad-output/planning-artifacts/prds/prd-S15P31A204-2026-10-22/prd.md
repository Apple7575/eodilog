# 어디로그 PRD

> 내 여행 피드를 지도에서 관리하고, 친구의 여행을 홈 지도에서 발견하며, 채팅으로 함께 다음 여행을 만든다.

## 1. 목적과 결정 상태

이번 회의의 18개 항목과 사용자의 후속 설명을 기준으로 **어디로그**를 다시 정의한다. 어디로그는 **지도를 중심으로 내 여행 피드를 관리하고, 친구의 여행을 발견·저장하며, 채팅으로 소통하는 여행 SNS**다. 개인·그룹 즐겨찾기, 공동 여행 계획, 여행 후 사진·평가·정산이 다음 여행 추천으로 이어진다. 모바일 플랫폼은 `[ASSUMPTION A-1]`이며 세부 배포 대상은 Q-1에서 결정한다.

사용자는 **회의에 나온 기능으로 새 PRD를 만들고 기존 PRD를 폐기한다**고 확정했다. 10월 14일 어디로그 문서는 이전 제품 맥락만 참고했다. 10월 21일 이어행 PRD와 그 기반 기능명세서·사용자 흐름은 현행 개발 근거가 아니다. 옛 요구사항 `FR-N`, `IE-FR-NN`, `FS-*`를 이번 요구사항으로 그대로 해석하지 않는다. 새 요구사항 ID는 `WD-FR-NN`이다.

**확정 범위:** 회의의 18개 항목 전체와 후속 설명으로 확인한 채팅, 사용자 흐름 검토에서 추가한 인앱 알림(v0.3, §4.11). 경비 계산·정산, 친구 추천도 포함한다. ‘기본 CRUD는 필수’라는 요청을 기능별 생성·조회·수정·삭제와 권한·자료 영향까지 구체화한다. 이번 초안에서 임의로 MVP를 줄이거나 기능을 후순위로 확정하지 않는다.

**승계하지 않는 범위:** 캠핑카·가족 근황·회상·영상 등 회의와 후속 설명에 없는 기존 기능은 이번 범위에 넣지 않는다. 채팅은 사용자 확인으로 포함하며, 상세 경계는 §9를 따른다.

**미확정:** 공동 피드 공개 내용·비공개 계정과의 결합, 10원 올림 차액 귀속, 실시간 공동 편집 방식과 저장/충돌/알림 묶음 등은 §10에 남긴다. 입력 우선순위는 **최신 사용자 요청 → 2026-10-27 결정 문서의 구체 수정(F) → 같은 문서의 Q 결정 → 최신 사용자 흐름 → 충돌하지 않는 v0.4 확정 → 회의 메모·문서 가정**이다. 구현 준비가 끝난 항목과 미정 항목을 구분하며 draft를 유지한다.

## 2. 제품 비전과 대상

가고 싶은 장소는 링크와 캡처에 흩어지고, 친구가 다녀온 여행은 사진만으로 장소·동선·이동 시간을 이해하기 어렵다. 함께 여행할 때는 각자의 저장 장소와 취향을 모아 합의해야 하고, 다녀온 뒤에는 사진 정리·평가·경비 정산이 남는다. 이는 회의에서 제기한 문제를 정리한 가설이며 사용자 조사로 입증된 사실은 아니다.

어디로그는 친구의 여행을 지도와 피드로 탐색하고, 가고 싶은 장소를 나만의 보관함 또는 동행의 공용 보관함에 저장하게 한다. AI는 저장 장소의 겹침과 각자의 취향을 반영해 맛집·여행 스팟을 추천하고, 동행은 투표로 목적지를 정한 뒤 코스를 만든다. 여행 중에는 날씨 대안·준비물·주변 편의시설·일정 재조정을 이용한다. 여행 뒤 사진·평가·이동거리·경비를 기록하고 공개할 범위를 골라 다음 사람의 여행 발견에 연결한다.

SNS의 핵심 화면은 **마이페이지의 내 피드 지도**와 **홈의 친구 피드 지도**다. 나는 지도 핀에서 내 기록·게시 내용·공개 범위를 관리하고, 친구는 홈 지도에서 자신에게 공개된 내 피드를 발견한다. 좋아요·장소 저장·친구 관계·채팅이 이 탐색을 소통과 다음 여행으로 연결한다. 친구에게 보이는 내용과 내가 관리하는 원본은 공개 설정에 따라 구분한다.

대상은 친구와 여행을 준비하거나, 친구 여행을 참고해 다음 여행을 계획하고, 본인의 여행 이력을 지도·타임라인으로 관리하려는 사람이다. 특정 연령층은 아직 확정하지 않았다. 친구가 적거나 과거 기록이 없어도 장소 저장과 여행 준비를 시작할 수 있어야 한다는 동작은 `[ASSUMPTION A-2]`다.

### 2.1 핵심 사용자 흐름

**친구 여행 발견 → 개인 즐겨찾기 → 동행 그룹·그룹 즐겨찾기 → 취향·겹침 기반 추천 → 여행지 투표 → 코스 구성 → 여행 안내·재조정 → 사진 정리·평가·경비 정산 → 내 지도·타임라인·선택 공유**

### 2.2 초안 사용자 여정

예시에 등장하는 인물은 **세은·승기·성환·영광·인경·수철**로 통일한다. 아래는 회의 기능을 연결한 **제안 여정 `[ASSUMPTION A-3]`**이며 실제 인터뷰 결과가 아니다. 화면 이름과 이동 순서는 UX에서 구체화한다.

- **UJ-1. 세은이 친구 여행을 다음 여행 후보로 담는다.** 세은은 홈 지도에서 자신에게 공개된 친구의 부산 여행을 발견한다. 사진·장소·경로·이동 시간을 확인하고 마음에 드는 카페를 개인 즐겨찾기에 담는다. 개인 보관함은 다른 친구에게 공개되지 않는다. 새로 저장한 장소를 다음 동행의 그룹 즐겨찾기에 명시적으로 추가한다.
- **UJ-2. 수철이 동행과 가고 싶은 곳을 모아 코스를 정한다.** 수철은 여행 그룹을 만들고 카카오톡 초대 링크를 공유한다. 구성원은 링크·캡처·개인 즐겨찾기에서 장소를 모은다. 수철은 지도에서 추출 장소를 확인·수정하고, 동행은 겹치는 저장 장소와 각자의 취향을 반영한 추천을 본다. 여행지를 투표로 결정하고 장소 간 이동 시간을 확인하며 코스를 구성한다.
- **UJ-3. 성환이 비 예보와 빠진 장소에 맞춰 여행을 조정한다.** 성환은 날씨 대안과 준비물 체크리스트를 확인한다. 방문할 장소 하나가 빠지자 자동 재조정 결과와 바뀐 동선·이동 시간을 확인한다. 변경안을 확인한 뒤 여행 멤버 누구나 적용할 수 있다. 전기차 충전소 등 주변 편의시설도 확인한다.
- **UJ-4. 승기가 여행 기록을 정리하고 친구별로 공유한다.** 승기는 여행 사진을 올리고 주제별 분류·비슷한 사진 묶음을 확인한다. 방문 장소에 평점·평가를 남기고 경비를 입력해 정산 결과를 본다. 마이페이지에서 지도·사진·이동거리·경비 요약과 타임라인을 관리한다. 여행당 하나인 공동 피드는 기본 전체 공개다. 승기는 자신의 프로필·피드에서 부산 여행을 특정 친구에게 숨길 수 있지만, 그 친구는 동행의 피드나 다른 경로에서 같은 여행을 볼 수 있다.
- **UJ-5. 인경이 여행 그룹 채팅으로 이야기를 이어간다.** 인경은 영광과 같은 여행에 참여해 투표·코스 시스템 카드를 확인하고 그룹 채팅에서 메시지를 주고받는다. 피드 열람만으로 채팅에 참여할 수 없다.

## 3. 용어와 자료 경계

| 용어 | 의미 |
| --- | --- |
| 친구·팔로우 | 화면의 친구 표현은 팔로우 관계를 기준으로 한다. 공개 계정 즉시 성립·비공개 계정 수락 후 성립. 별도 상호 친구 관계는 확정하지 않음 |
| 동행 그룹 | 여행마다 새로 만드는 구성원 공간. 팔로우와 여행 참여는 별도 권한 |
| 여행 | 목적지·기간·장소·코스·사진·평가·경비를 연결하는 기록 단위 |
| 여행지 | 투표로 정할 목적지·지역. 개별 장소와 구분하며 지역·개별 장소 투표를 모두 제공 |

| 여행 기록 | 여행에서 실제 방문·활동한 장소, 사진·평가·이동거리·경비 등 남긴 자료 |
| 공동 피드 | 여행당 하나인 공개 표현, 기본 전체 공개. 그룹 내부 원본 전체와 구분 |
| 개인 피드 노출 | 공동 여행 피드를 자신의 프로필·피드에 노출하는 방식. 특정 친구에게 숨겨도 다른 경로의 공동 피드 열람은 막지 않음 |
| 개인 즐겨찾기 | 본인만 열람·관리하는 장소 보관함 |
| 그룹 즐겨찾기 | 동행 그룹 구성원이 함께 모으고 여행 추천에 활용하는 장소 보관함 |
| 취향 | 사용자가 선택하거나 허용한 행동·기록에서 얻는 여행 선호. 입력·추론 기준은 Q-5 |
| 좋아요 | 다른 사람에게 추천할 때 활용할 긍정 반응. 대상이 피드/장소 중 무엇인지 Q-5 |
| 평점·평가 | 여행 후 방문 장소에 남기는 점수와 후기. 점수 체계·작성 자격은 Q-7 |
| 정산 | 여행 경비·지출자·분담 대상/금액을 바탕으로 구성원별 부담액과 주고받을 금액을 계산하는 기능 |
| 채팅 | 여행 멤버만 참여하는 여행당 그룹 채팅. 1:1 제외 |
| 알림 | 팔로우·투표·여행 참여/정보 변경·AI/코스 변경·공동 피드 삭제 등의 인앱 안내. 행동 필요 이벤트만 팝업 |

동행 그룹의 공동 원본, 친구에게 공개할 피드, 개인 즐겨찾기는 서로 다르다. **친구라는 이유로 공동 원본 전체를 열 수 없고, 동행이라는 이유로 개인 즐겨찾기를 열 수 없다.** 공동 피드와 개인 피드 노출 설정을 분리한다. 특정 친구 숨김은 설정한 멤버의 프로필·피드에서만 적용하며, 다른 경로로 같은 공동 피드를 보는 권한을 철회하지 않는다. 공개할 내용과 비공개 계정 설정의 결합은 Q-3에서 정한다.

## 4. 기능 요구사항

각 FR의 검증 조건은 해당 기능을 구현할 때 확인할 최소 기대 동작이다. 가정과 Q가 붙은 세부 기대값은 합의 뒤 확정한다. 기본 CRUD는 §5의 권한·삭제 영향과 함께 적용한다.

### 4.1 가입·사용자·친구·동행 그룹 — 회의 14·18

**WD-FR-01. 가입·프로필·연령 정보.** 카카오·네이버 로그인을 제공한다. 사용자는 가입하고 프로필을 조회·수정·탈퇴할 수 있으며 공개/비공개 계정을 설정한다. 가입 시 연령 입력 항목을 제공하되 필수 여부·나이/연령대·수정·보관·추천 사용 동의와 필수 프로필 항목은 Q-1이다. **검증:** 연령을 공개 프로필에 자동 노출하지 않는다. 탈퇴 시 자료·공유·정산 영향은 §6과 Q-10·11에 따른다. 로그인 제공자별 계정 연결은 후속 설계에서 정한다.

**WD-FR-02. 팔로우 관계 관리.** 공개 계정은 즉시, 비공개 계정은 요청 수락 후 단방향 팔로우가 성립한다. 요청 취소·거절·언팔로우와 받은 요청 관리를 제공한다. 사용자 검색은 닉네임만 사용한다. **검증:** 반대 방향 관계와 독립이며 팔로우만으로 여행 내부·그룹 채팅에 접근하지 않는다. 계정 공개 전환의 기존 대기 요청·차단·팔로워 제거 세부는 Q-2다.

**WD-FR-03. 사용자 추천·추천 숨김.** 공개 가능한 근거로 팔로우 후보를 추천한다. 사용자가 추천에서 숨긴 사람은 다시 추천하지 않는다. **검증:** 숨김은 새로고침·재접속 후에도 유지되며 추천/검색 결과를 팔로우로 자동 전환하지 않는다. 비공개 위치·연령·관계 정보를 추천 이유로 노출하지 않는다. 추천 근거와 차단은 Q-2다.

**WD-FR-04. 여행·그룹·링크 참여.** 여행마다 새 그룹을 만들고 이름만 필수, 기간·여행지는 나중에 지정할 수 있다. 모든 멤버가 이름/기간/여행지를 수정하고 링크로 초대하며 변경 시 멤버에게 알린다. 링크를 받은 로그인 사용자는 팔로우 관계 없이 참여하며 초대 코드는 없다. 방장만 내보내기·여행 삭제·양도를 할 수 있다. 방장 이탈 시 가장 먼저 가입한 잔여 멤버에게 양도하고 대상자를 미리 표시한다. 마지막 방장의 나가기는 여행 삭제와 동일하게 처리한다. **검증:** 무효/만료/이미 참여를 구분하고 중복 참여를 만들지 않는다. 일반 이탈 때 본인 사진·채팅 삭제를 선택하며 경비·공동 피드는 보존한다. 마지막 멤버의 여행 삭제는 일반 이탈과 구분해 삭제 영향을 안내한다. 여행 상태는 기간에 따라 자동 전환하며 날짜 미정/시간대/경계 규칙은 Q-4다.

**WD-FR-04 추가 확정(2026-10-30):** 여행 정원은 방장 포함 ACTIVE 멤버 최대 20명이다. 수락 시점에 정원을 검사하고 이탈·내보내기로 빈자리가 생기면 참여할 수 있다. 동시 수락으로도 20명을 초과하지 않아야 한다. 초대 링크는 발급 후 7일(168시간) 유효하며 만료 시각부터 참여할 수 없다. ACTIVE 멤버 누구나 재발급할 수 있고, 재발급하면 이전 링크는 즉시 무효화한다. 기존 참여자는 링크 만료·재발급의 영향을 받지 않는다.

### 4.2 링크·캡처와 즐겨찾기로 장소 모으기 — 회의 1·8

**WD-FR-05. 링크·캡처 장소 추출.** URL·캡처를 등록해 추출 후보를 지도에서 확인·수정·제거한다. 캡처는 한 번에 최대 10장이다. **검증:** 11장 이상을 거부하고 성공·복수 후보·식별 불가·실패를 구분한다. 잘못된 후보를 수동 검색/위치 지정으로 보정하며 근거 없는 좌표를 자동 확정하지 않는다. 지원 사이트·용량·장소 동일성·원본 보관은 Q-5·11이다.

**WD-FR-06. 개인 즐겨찾기.** 장소를 개인 보관함에 저장·조회·수정·해제하고 그룹 추가는 명시적으로 선택한다. **검증:** 본인만 열람하며 저장 시 개인/그룹을 고른다. 참여 중인 여행이 없으면 그룹 저장은 비활성화하고 이 경로에서 새 여행을 만들지 않는다. 원본 공동 피드 삭제/권한 상실 후 장소 이름·위치·내 메모만 남기고 원본 사진·본문·평가·출처 표현은 제거한다.

**WD-FR-07. 그룹 즐겨찾기·실시간 공동 편집.** 멤버가 장소를 모으고 저장자·겹친 장소를 함께 확인한다. 지금 보고 있거나 편집 중인 멤버를 표시하고 변경을 실시간 동기화한다. **검증:** 개인 저장은 자동 공개하지 않으며 저장만으로 코스에 추가하지 않는다. 타인 저장 메모 편집 권한은 Q-4, 전송/접속 표시/재접속 충돌 정책은 Q-15다.

### 4.3 취향·겹침·좋아요·트렌드 추천 — 회의 1·3·8·13

**WD-FR-08. 각자의 취향 반영.** 사용자는 여행 선호를 준비하고 허용된 범위에서 동행 추천에 활용한다. 취향 직접 입력은 기록 없는 사용자를 위한 `[ASSUMPTION A-2]`다. **검증:** 새 사용자는 과거 사진 분석 완료 없이 추천 입력을 준비할 수 있다. 사용자 선택과 행동에서 추론한 선호를 구분하고 타인의 선호를 본인의 것으로 단정하지 않는다. 취향 입력·공유·갱신 방식은 Q-5다.

**WD-FR-09. 그룹 저장 겹침·취향 기반 맛집·스팟 추천.** AI는 그룹 즐겨찾기의 동일 장소·선호 겹침과 각자 허용한 취향을 반영해 여행지·맛집·스팟을 추천한다. **검증:** 반영한 입력 범위와 추천 이유를 설명하고, 한 사람의 저장을 동행 전체 합의로 표시하지 않는다. 겹침 없음·자료 부족·생성 실패를 구분하며 겹침 계산·가중치·재추천 정책은 Q-5다.

**WD-FR-10. 좋아요 기반 다른 사용자 추천.** 사용자의 좋아요를 추천 신호로 활용해 다른 사용자가 관심을 가질 장소·여행을 제안한다. **검증:** 좋아요와 실제 방문·평점을 구분하고, 좋아요 취소 시 이후 추천 입력의 반영 정책을 따른다. 비공개 여행의 위치·사진·반응자를 추천으로 드러내지 않는다. 대상·가중치·다른 사용자에게 활용할 범위는 Q-5다.

**WD-FR-11. 최근 트렌드 여행지 추천.** 사용자는 최근 관심을 받는 여행지와 추천 근거를 확인한다. 평점·좋아요·취향·연령은 기준 후보이며 모두 사용하기로 확정한 것은 아니다. **검증:** 기준 기간·집계 대상·정보 갱신 시점을 표시하고, 자료가 부족하면 ‘최근 트렌드’로 단정하지 않는다. 비공개 자료의 활용·집계 노출과 연령 활용은 Q-5·9에서 정한다.

### 4.4 투표·코스·이동 시간·재조정 — 회의 2·10·17

**WD-FR-12. 지역·장소 투표.** 그룹 즐겨찾기·추천에서 후보를 체크하고 투표를 연다. 두 유형 모두 복수 선택이며 마감은 필수·기본 현재 시각으로부터 24시간 후다. 마감 전에는 모든 멤버가 후보 추가·선택 변경/취소를 할 수 있다. 마감시각에 서버가 자동 집계해 최다 후보 전부를 확정하고 동률도 모두 확정한다. 0표면 확정 없이 마감한다. **검증:** 방장 수동 종료/확정·전원 참여 조기 종료를 제공하지 않는다. 마감과 쓰기 경합을 원자 처리하고 중복 확정을 막는다. 후보 추가는 이미 투표한 멤버에게 알리고 마감 1시간 전 미투표자에게만 알린다. 복수 지역은 코스에서 날짜별 배분하고 확정 장소는 코스 후보 상단에 둔다. 참가자 변동·후보 삭제·짧은 마감의 사전 알림은 Q-6이다.

**WD-FR-13. 단일 코스·실시간 공동 편집.** 자동 추천/직접 만들기를 모두 제공하며 모든 멤버가 날짜별 장소·순서를 함께 편집한다. 저장 성공 즉시 현재 코스에 반영한다. 편집안과 확정본을 분리하지 않고 확정 버튼·승인 요청은 두지 않는다. **검증:** 그룹 즐겨찾기에서 날짜별로 후보를 배치하고 여러 지역을 날짜별 배분한다. 접속·편집 멤버를 표시하며 실패 시 현재 코스를 보존한다. 별도 충돌 안내 화면은 연결이 끊겼다 복귀하는 경우에만 둔다. 실시간 전송·저장 버튼의 역할·동시 쓰기 처리/재접속은 Q-15다.

**WD-FR-14. 구간별 이동 수단·시간·경로.** 날짜별 인접 장소 사이마다 자동차·대중교통·도보를 선택하고 경로·이동 시간을 지도/목록에서 본다. **검증:** 코스 전체 단일 수단을 강제하지 않는다. 순서/장소/수단 변경 시 영향을 받는 구간을 다시 계산하고 실패는 0분·직선 이동으로 대체하지 않는다. 계획과 실제 거리·방문은 구분하며 실제 기록 기준은 Q-8이다.

**WD-FR-15. AI 변경안 적용·1단계 되돌리기.** 장소 제외·날씨 변경의 AI 결과를 현재 코스와 비교하고 모든 멤버가 적용할 수 있다. AI는 제안만 하고 적용 전/실패 시 현재 코스를 유지한다. 적용 직후 바로 이전 코스로 1단계 되돌릴 수 있다. **검증:** 승인 단계와 별도의 오래된 변경안 확인 화면은 없다. 동시 편집 결과를 조용히 덮어쓰지 않아야 하며 적용 시점 경합/재계산·되돌리기 유효 시점은 Q-15에서 합의한다. 버전 검사는 서버 제안이지 추가 확인 화면 요구가 아니다. 적용/되돌리기는 코스 변경 알림 대상이고 묶음은 Q-16이다.

### 4.5 여행 중 날씨·준비물·편의시설 — 회의 15·16

**WD-FR-16. 날씨 대안 추천.** 여행 날짜·장소·일정을 바탕으로 날씨 영향과 대체 장소·활동을 안내한다. **검증:** 날씨 조회 시점과 갱신 실패를 표시하며, LLM이 조회하지 않은 날씨·영업 정보를 사실로 생성하지 않는다. 대안 선택과 코스 변경을 구분한다. LLM 활용 의도는 [설계 입력](./addendum.md)에 보존하며 공급자는 확정하지 않는다.

**WD-FR-17. 공동 준비물 목록.** 여행당 공동 목록 하나에서 항목을 추가·수정·삭제·체크하고 체크한 멤버를 표시한다. 날씨·일정 기반 제안을 채택할 수 있다. **검증:** 모든 멤버에게 같은 목록/체크 상태를 보여주고 해제 시 체크한 사람도 비운다. 재추천은 직접 수정·체크한 항목을 덮어쓰지 않는다. 동시 편집은 버전으로 보호하며 구체 동기화 방식은 Q-15다.

**WD-FR-18. 스팟 주변 편의시설.** 추천·계획 장소 주변의 전기차 충전소·주유소 등 편의시설을 지도에서 확인한다. **검증:** 기준 장소·시설 유형·조회 범위를 구분하고 조회 실패/결과 없음을 따로 안내한다. 실시간 이용 가능 여부나 충전기 가동 여부는 확인된 경우에만 표시한다. 시설 종류·반경·정보 공급원·필터는 Q-8이다.

### 4.6 사진 자동 정리·방문 후 평가 — 회의 4·5

**WD-FR-19. 사진 수집·관리.** JPG·PNG·HEIC를 한 번에 최대 50장 올려 여행·장소에 연결하고 조회·보정·삭제한다. **검증:** 51장 이상/지원 외 형식을 거부하고 부분 실패 시 성공분을 보존한다. 파일 형식 판별·용량·HEIC 표시 변환·공동 자료 편집 권한·보존은 Q-7·11이며 장수 상한을 총 여행 저장 한도로 해석하지 않는다.

**WD-FR-20. 사진 주제별 분류·비슷한 사진 묶기.** 사진을 주제별로 분류하고 비슷한 사진을 묶어 열람·관리한다. **검증:** 분류·묶음 결과와 원본을 구분하고 잘못된 분류·묶음을 고칠 수 있다. 비슷하다는 이유로 원본을 자동 삭제하지 않는 동작은 `[ASSUMPTION A-7]`이다. 주제 목록·한 사진의 복수 주제·유사 기준·재분류는 Q-7이다. 베스트 컷 선정·영상 생성은 이번 요구로 추가하지 않는다.

**WD-FR-21. 방문 장소 평점·평가.** 실제 방문한 장소에 1~5점 정수 별점과 평가를 작성·조회·본인 수정/삭제한다. 반 점은 제공하지 않는다. 방문은 사진 위치/날짜 확인 또는 직접 다녀옴 체크로 연결한다. **검증:** 계획만 있고 방문 확인하지 않은 장소는 평가 대상이 아니며 타인 평가는 변경할 수 없다. 사진 판정 오차·중복 평가·공개 집계는 Q-7이다.

### 4.7 경비 기록·최종 정산 — 회의 2·9·12

**WD-FR-22. 원화 여행 경비 관리.** 지출별 결제자·분담자를 선택해 균등 분담하며 등록자만 수정·삭제한다. 원화(KRW) 양수 정수만 사용한다. **검증:** 방장/결제자라도 다른 등록자의 지출 변경을 막고 외화 입력을 거부한다. 변경은 합계·재계산 필요 상태에 반영하고 이탈자의 기존 경비를 유지한다. 1인 부담액 올림과 원금 분담을 구분하며 이탈 후 편집은 Q-10이다.

**WD-FR-23. 정산 계산·1인 부담액 올림.** 선택한 분담자들의 1인 부담액을 10원 단위로 올려 낸 돈·부담액·누가 누구에게 보낼지 계산하고 올림 안내를 표시한다. 완료/미완료 표시·완료 알림·송금/결제는 없다. **검증:** 원금과 올림 부담액·차액을 구분하고 비용 변경 후 이전 결과를 최신으로 표시하지 않는다. 올림을 지출별/여행 누적 중 언제 적용할지와 차액 귀속·재계산은 Q-10이며 합계 일치를 위해 임의 수령자를 지정하지 않는다.

**WD-FR-23 추가 확정(2026-11-02):** 사람별 원금 분담 합계를 여행 전체로 더한 뒤 한 번만 10원 단위로 올리고(지출별 올림 없음, 0원은 0원), 올림 차액은 원금 기준 받을 돈(결제 합계 - 원금 부담 합계)이 가장 많은 한 사람에게 귀속한다(동률은 joinOrder·memberId 순, 모두 0이면 결제 합계가 가장 큰 사람, 경비가 없으면 차액 0·수령자 없음). 이전 계산은 여행이 있는 동안 보관하고 경비가 바뀌어도 과거 계산을 덮어쓰지 않는다.

### 4.8 홈 지도·친구 여행·내 피드·타임라인 — 회의 2·6·7·11·12

**WD-FR-24. 홈 친구 여행 지도.** 메인페이지 지도에서 자신에게 공개된 친구의 방문 위치를 탐색하고 관련 여행 피드로 이동한다. **검증:** 본인 권한에 없는 위치·마커 수·사진을 표시하지 않고, 같은 지역의 복수 여행도 식별 가능한 경로를 제공한다. 친구/기록 없음·지도 실패를 구분한다. 표시 지역 범위·기본 위치·기간·마커 묶기는 Q-8이다.

**WD-FR-25. 많이 간 지역·다른 지역 구분.** 홈 지도에서 많이 방문한 지역과 그 외 방문 지역의 차이를 표현한다. 회의의 ‘다르게 간 지역’은 희소 방문/내가 안 간 지역 등 해석이 가능하므로 정확한 의미는 Q-8에서 결정한다. **검증:** 집계 기준·기간·대상을 확인할 수 있고, 추천 노출이나 좋아요 수를 실제 방문 횟수로 대신하지 않는다. 색 외 구분 표현은 UX에서 제안한다.

**WD-FR-26. 친구 여행 상세 탐색.** 친구에게 허용된 여행지·사진·경로·이동 시간·평점/평가·경비를 함께 파악하고 장소 저장으로 이어간다. **검증:** 선택 마커와 상세 여행이 일치하고, 미공개 항목을 숨기며, 공동 피드 삭제 또는 실제 열람 권한 상실 시 접근을 막는다. 개인 피드에서의 숨김은 다른 경로의 공동 피드 열람을 막지 않는다. 상세에 기본 표시할 항목과 단위는 Q-3이다.

**WD-FR-27. 마이페이지 내 피드 지도·관리.** 사용자는 자신의 피드를 핀이 있는 지도에서 보고 여행 기록·공개 정보를 관리한다. **검증:** 본인 관리 화면과 다른 사람이 보는 화면을 구분하고, 장소 위치를 바꾸거나 기록을 삭제하면 지도에도 반영한다. 특정 친구에게 숨긴 여행은 본인의 프로필·피드 및 그에 연결된 본인 지도 노출에서 제외한다. 다른 멤버의 피드나 다른 경로에서 같은 여행이 보이는 것은 허용한다.

**WD-FR-28. 공동 피드 게시·삭제·개인별 숨김.** 멤버가 공동 피드 게시를 눌러야 여행당 하나의 공동 피드가 생성된다. 게시 후 기본 전체 공개이며 멤버 누구나 게시/삭제한다. 사진 공개 동의·항목별 공개 설정은 없다. 각 멤버는 자신의 프로필·피드·지도 경로에서 특정 친구에게 그 여행을 숨기거나 다시 표시할 수 있다. **검증:** 승기가 수철에게 숨겨도 세은의 경로나 직접 공동 피드 경로에서는 볼 수 있다. 숨김은 전역 접근 거부가 아니다. 공동 피드 삭제는 모든 멤버 경로에서 제거하고 다른 멤버에게 알리되 여행/사진/경비 원본 삭제를 뜻하지 않는다. 게시 알림은 보내지 않는다. 공개 내용·비공개 계정 결합·삭제 후 재게시는 Q-3이다.

**WD-FR-29. 여행별 타임라인.** 여행 시작일 최신순으로 표시하고 날짜 없는 여행은 맨 아래 날짜 미정 묶음에 둔다. **검증:** 같은 날짜의 안정적인 정렬과 계획/실제 방문 구분을 유지하고 타인은 허용된 공동 피드 경로만 본다. 장소별 상세 활동 단위는 Q-8이다.

**WD-FR-30. 여행 요약 카드.** 지도·사진·이동거리·경비가 연결된 여행 요약 카드를 확인한다. **검증:** 요약이 어떤 여행·기간에 대한 것인지 표시하고, 미입력 비용·미확인 이동거리를 임의 계산값으로 채우지 않는다. 타인에게 보이는 카드는 공개 허용 항목만 포함한다. 실제/계획 거리, 경비 공개·합산 범위는 Q-3·8·10이다.

### 4.9 좋아요·기본 관리 — 회의 3·18

**WD-FR-31. 좋아요 관리.** 사용자는 허용된 대상에 좋아요를 남기고 상태를 조회·취소한다. 대상·중복·타인 반응 열람·합계 공개는 Q-5다. **검증:** 같은 행동의 반복 전송으로 수가 중복 증가하지 않고 취소가 상태에 반영된다. 좋아요로 방문 완료나 평점 작성을 대신하지 않는다.

**WD-FR-32. 기능별 기본 관리와 삭제 영향.** 사용자 생성 자료는 §5의 CRUD 범위를 제공하고, 권한 없는 변경을 막으며 변경 후 관련 지도·피드·추천·정산에 미치는 영향을 반영한다. **검증:** 성공·실패·빈 상태·삭제·접근 상실을 구분한다. 삭제 실패를 성공으로 표시하지 않고 본문·첨부·파생 결과의 보관 범위를 합의한 뒤 적용한다. 삭제·복구·보존의 정확한 기간은 Q-11이다.

### 4.10 채팅 — 사용자 후속 확정

**WD-FR-33. 여행 그룹 채팅.** 여행당 그룹 채팅방 하나에서 현재 멤버가 메시지를 조회·전송한다. 1:1 채팅·새 개인 대화 생성은 제외한다. **검증:** 실패 재시도·중복 전송 방지와 비참여자/이탈자의 접근 차단을 제공한다. 피드 열람·팔로우는 채팅 참여 권한을 부여하지 않는다. 이탈 시 본인 채팅 삭제 선택은 유지한다. 2026-11-02 Q-13 확정: 현재 ACTIVE 멤버(신규·재참여)는 처음부터 전체 이력을 보고, 읽음·첨부·일반 메시지 수정/삭제는 추가하지 않는다. 보존은 Q-13이다.

### 4.11 인앱 알림 — 사용자 흐름 검토 추가 (v0.3)

**WD-FR-34. 인앱 알림·시스템 메시지.** 팔로우 요청/수락, 투표 시작·후보 추가·마감 1시간 전 미참여 알림·자동 결과, 멤버 참여·여행 정보 변경, AI 변경안·코스 변경, 공동 피드 삭제를 관련 당사자에게 전달한다. 게시·방장 양도·코스 승인·정산 완료·사진 공개 동의 알림은 없다. 팝업은 투표 시작/마감 전·팔로우 요청·AI 변경안처럼 내 행동이 필요한 것만 보여주고 나머지는 알림 목록에 둔다. 여행 이벤트는 여행 그룹 채팅 시스템 카드와 연결하고 읽음을 동기화한다. **검증:** 권한/참여/미투표 상태를 전송·조회·이동 때 재검사하고 이벤트를 중복 생성하지 않는다. 푸시는 제외한다. 코스 연속 변경 묶음은 Q-16, 보관/팝업 세부는 Q-14다.

### 4.12 AI·알림 설정 — 화면 S45

**WD-FR-35. 기능별 AI·알림 설정.** 프로필·취향·설정에서 AI 기능과 알림 수신 설정을 관리한다(S45). 기존 API의 설정 계약을 유지하며 사진 분류·방문 판정·추출·준비물의 AUTO/CONFIRM/OFF와 날씨 SUGGEST_ONLY/OFF는 구체화 제안 D-19다. **검증:** 설정 변경 실패 시 이전 값을 유지하고 본인만 수정한다. AI 설정이 여행 멤버십·사진 사용 동의·코스 버전 검사를 우회하지 않는다. 날씨/코스는 사용자가 변경안을 적용해야 바뀐다. 종류별 초기값·진행 중 작업 영향·알림 설정과 필수 안내 우선순위는 Q-11·14에서 합의한다.

## 6. 공유·개인정보·자료 생명주기

1. **개인 저장:** 개인 즐겨찾기는 본인만 접근한다. 그룹 활용은 사용자가 명시적으로 선택한 장소에 한정한다.
2. **그룹 원본:** 여행 공동 자료는 그룹의 역할·권한에 따라 접근한다. 친구 피드를 볼 수 있다는 이유로 공동 원본을 열지 못한다.
3. **공동 피드와 개인 노출:** 게시 전 공동 피드는 없고 게시 후 기본 전체 공개다. 특정 친구 숨김은 본인 경로만 제외하며 직접 링크·타 멤버 경로의 공동 피드를 막지 않는다. 사진 공개 동의·항목별 설정 없이 공개할 내용과 비공개 계정 결합은 Q-3에서 결정한다. 공동 피드 삭제는 모든 노출·파일·요약에 반영하고 저장 장소에는 이름·위치·내 메모만 남긴다.
4. **추천 경계:** 비공개 자료를 통해 특정인의 위치·이동·경비·관계가 드러나지 않아야 한다. 추천 학습/입력에 쓸지와 타인에게 보여줄 수 있는지는 별도 정책으로 정한다(Q-5·9).
5. **연령·위치:** 연령의 수집 형식·필수 여부·공개·추천 활용을 분리한다. 현재 위치를 수집하거나 실시간 위치를 공유하기로 정한 것은 아니다. 캡처 속 불필요한 개인정보·사진 메타데이터·외부 AI 전송 범위도 Q-11에서 정한다.
6. **철회·삭제·탈퇴:** 공동 피드 자체 삭제나 실제 권한 철회는 직접 링크·파일·목록·마커·추천·요약에도 적용한다. 개인 피드에서 특정 친구에게 숨긴 것만으로 공동 피드의 전역 열람을 차단하지 않는다. 그룹 이탈 시 본인 사진·채팅 삭제 여부를 선택하고 경비는 유지하며, 구체 삭제 범위는 Q-11·13이다. 과거 즐겨찾기에 저장한 공개 장소 정보와 원작성자의 비공개 사진·평가는 구분한다. 삭제한 원본·기존 파생 결과·정산 기록·공동 자료를 언제까지 보존할지는 Q-11이다. 이전 PRD의 영구 보존·최근 삭제함 규칙을 자동 적용하지 않는다.
7. **채팅:** 현재 여행 멤버십으로 그룹 채팅 접근을 검사한다. 1:1은 제외하며 이탈·내보내기·여행 삭제 시 이후 수신을 차단한다. 채팅 내용을 추천·피드에 자동 활용하지 않는다. 현재 ACTIVE 멤버는 처음부터 전체 이력을 보고(Q-13, 11/02), 보존은 Q-13이다.
8. **알림:** 알림 본문에 비공개 자료(위치·경비·관계)를 담지 않고, 이동 버튼을 눌렀을 때 해당 화면의 권한을 다시 검사한다. 권한을 잃은 사용자에게는 이후 알림을 보내지 않는다(v0.3).

통합 인수는 다음 조건을 포함한다. Q에 해당하는 정책은 합의한 뒤 정확한 기대값을 채운다.

추천의 정상 결과는 [설계 입력의 대표 검증 사례](./addendum.md)로 확인한다. 정확한 순위·추천 개수·점수는 알고리즘 정책 합의 뒤 고정하며, 현재는 입력 반영·설명·공개 경계를 먼저 검증한다.

- 링크 성공·복수 후보·실패와 캡처 장소 오인식 수정, 저장 목적지 선택.
- 같은 장소를 세은·승기가 저장했을 때 그룹 겹침 반영, 인경의 개인 보관함 비노출.
- 공개/비공개 계정의 즉시 팔로우/요청 대기/수락 상태와 그룹 내부 비참여자 접근 차단 확인.
- 친구가 없는 신규 사용자의 탐색·장소 저장·취향 준비 경로, 후보 없는 친구 추천.
- 투표 중/현재 코스 구분, 장소 하나 제외 후 자동 재조정·이동시간 변경·실패 시 보존.
- 오래된 날씨·조회 실패·시설 정보 없음·준비물 편집 후 재추천.
- 사진 부분 실패·잘못된 주제·유사 묶음 보정, 방문 후 평점 수정/삭제와 집계 갱신.
- 여러 지출자의 비용 합산·다른 분담 대상·소수점/반올림·지출 수정/삭제·정산 후 변경.
- 개인 지도·타임라인·요약의 날짜/거리/경비 미입력 상태, 공개 철회 이후 파생 표시 갱신.
- 승기가 부산 여행을 수철에게 숨기면 승기의 프로필·피드에서 제외되지만 세은의 피드나 다른 경로에서는 같은 공동 피드를 볼 수 있음.
- 지역·장소 모두 복수 선택, 시각 마감 자동 확정·동률 최다 모두·0표는 확정 없이 마감. AI 변경안은 멤버 누구나 비교 후 적용.
- 지출별 선택 인원 균등 계산, 등록자 외 수정·삭제 차단, 송금 완료 표시 없이 계산 결과만 제공.
- 방장 이탈 시 잔여 멤버 중 가입 순서가 가장 빠른 사람에게 양도, 본인 사진·채팅 삭제 선택 및 경비 유지.
- 채팅의 전송 실패·재시도·중복 방지, 비참여자의 직접 접근 차단. 친구 해제·차단·그룹 이탈 후 수신과 과거 대화는 Q-13의 합의값으로 검증.
- 투표 시작 뒤 다른 구성원이 채팅 시스템 메시지와 앱 실행 팝업 중 하나로 투표 화면에 도달. 그룹을 나간 사용자에게는 이후 알림 없음(v0.3).

- 닉네임 검색만·추천 숨김 재노출 없음, 팔로우 양방향 독립.
- 관계 없는 링크 참여·코드 없음, 마지막 방장 이탈=여행 삭제, 기간 자동 상태 전환.
- 게시 버튼 전 피드 없음·게시 후 여행당 하나, 모든 멤버 삭제·게시 알림 없음·삭제 알림, 특정 친구 숨김의 본인 경로만 제외.
- 기본 24시간 투표·진행 중 후보 추가·변경/취소·마감 1시간 전 미투표자 알림·동률 모두·0표 미확정.
- 캡처 10/11장·사진 50/51장과 JPG/PNG/HEIC, 1~5점 정수·타인 평가 변경 차단.
- 구간별 수단·공동 실시간 편집·접속 표시·1단계 AI 되돌리기(Q-15 합의 후 경합 기대값 추가).
- 1인 부담액 10원 올림과 차액(Q-10 합의 후)·공동 준비물 체크 멤버·날짜 미정 타임라인 마지막.
- 1:1 생성 경로 없음·그룹 채팅 비참여자 차단, 원본 피드 삭제 뒤 이름/위치/내 메모만 보존.

## 9. 이번 범위에 포함하지 않는 기존 기능

기존 문서의 캠핑카 성장·꾸미기, 가족 근황·AI 대화 제안, 회상 카드, 연말 영상·하이라이트·AI 게시글 초안, 새로움 비율 조절, 옛 사진 인터뷰·퀴즈·건강 평가를 자동 승계하지 않는다. **채팅은 사용자 후속 설명으로 포함한다.** 댓글·베스트 컷·실시간 위치 공유·자동 도착 알림·외부 드라이브 연동·원본 영상 업로드도 회의나 후속 요구 근거 없이 추가하지 않는다. **푸시 알림**은 PWA·iOS 제약과 일정을 고려해 범위 밖으로 두고, 알림은 앱 안의 팝업·채팅 시스템 메시지로만 제공한다(WD-FR-34).

경비 계산·정산은 포함하지만 실제 송금·결제·계좌 연동까지 포함하는 것은 아니다. 링크 등록은 모든 SNS 비공개 콘텐츠나 로그인 필요 페이지를 가져올 수 있다는 보장이 아니다. 친구 추천은 추천 기능이며 낯선 사람과의 자동 동행 매칭을 뜻하지 않는다.

## 12. 후속 산출물과 사용 기준

현행 문서 기준은 이 PRD v0.6과 [API v0.4](../../../../docs/api-spec.md)·[ERD v0.4](../../../../docs/erd.dbml)다. 결정 문서/사용자 흐름과의 충돌은 §1.1에 기록했다. `docs/flow`와 원본 결정 기록을 이번 작업에서 다시 쓰지는 않으며 명시한 충돌은 이 PRD를 우선한다. 과거 [설계 입력](./addendum.md)·리뷰는 현행 정책과 일치하는 부분만 참고한다.

C-1~C-51 원문 대조와 팀 전체 합의가 완료됐다는 뜻은 아니다. 확정 정책을 API/ERD에 반영하되 미정 기술/차액/공개 세부는 제안으로 구분한다.

미정 정책 합의·입력 대조·검토 후에 최종 확정 상태를 부여한다. 이번 초안 작성 자체로 기능의 API·DB·화면 배치·개발 담당자·일정이 확정되지는 않는다.
